# 一年研究路线与预算

> 本文保留最初本地阶段/一年路线的范围。后续授权的必做 GPU 技术实验已于 2026-10-22 通过完整验收；最新证据与限制以 [README](../README.md#技术验收与证据) 和[技术执行约定](study-workflow.md)为准，论文等提交物仍不属于本次技术交付。

目标是研究一个可检验的方法：根据形状、数据复用与融合需求缩小 Triton 候选配置空间，在降低搜索成本的同时保留性能；不是简单照抄教程或预先宣称全面超过成熟库。

| 月份 | 工作 | 验收里程碑 |
|---|---|---|
| 1–2 | GPU 基础、CPU 数学参考、Triton 入门、文献阅读 | 能解释并测试 GEMM/softmax/online softmax，建立统一计时工具 |
| 3–4 | GEMM 分块、调度和融合 | 正确性通过，形成消融和退化清单 |
| 5–6 | Attention 前向与显存分析 | 对比数学 SDPA 与成熟融合 SDPA，解释长短序列差异 |
| 7 | 受限卷积验证、申请校内算力 | 清楚列出布局/地址计算成本与硬件权限要求 |
| 8–9 | 固定、有限搜索、形状规则筛选 | 固定规则后在未参与规则设计的形状评测；报告在线调参成本 |
| 10 | 正式实验、模型模块级验证 | 固定代码/环境/硬件，多次独立运行；有条件增加第二种 GPU |
| 11–12 | 补实验、论文与复现 | 强基线、失败案例、局限、原始数据与答辩材料齐全 |

本次本地阶段提前实现代码和实验设施，不能把上述 GPU 里程碑标记为已完成。反向算子、GQA、KV cache、训练和多卡均不属于当前交付。

## 研究决策门槛

1. 正确性不通过：保留失败输入与配置，修内核，不继续报告该配置性能。
2. 仅超过朴素基线：视为复现结果，继续与成熟后端比较，不宣称创新。
3. 规则筛选使部分形状退化：完整报告，分析资源限制/边界块/并行度，不删除失败形状。
4. 无 profiling 权限：可以报告可重复延迟与显存，但不能把瓶颈猜测写成硬件事实；申请可访问性能计数器的主机。
5. 单算子收益未转化到模块：分析残差、归一化、布局搬运、launch 和其他计算占比，不把单算子倍数当模型倍数。
6. 预算不足：保留强基线与正确性，减少第二种 GPU 与扩展任务；不隐瞒测试覆盖减少。
